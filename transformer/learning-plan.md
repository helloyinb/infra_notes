# Transformer 论文学习计划

## 目标与节奏

学习结束时，能够独立画出原版 Transformer，解释各模块的输入输出与设计理由，追踪张量形状，实现一个小型 Encoder–Decoder，并说明它与现代 Decoder-only 模型的联系。

结合仓库中的 AI Infra 总路线，第 6 周加入计算量、KV Cache 与推理阶段的分析。前五周集中理解模型本身，完整复现 WMT 翻译成绩不作为本阶段目标。

- 建议周期：6 周，每周 6～8 小时，分为 3～4 次学习。
- 默认基础：会写 Python，知道矩阵乘法和梯度下降；PyTorch 不熟悉时先补基础。
- 每次学习：约 30～45 分钟精读，45～60 分钟推导或实践，15 分钟记录问题与结论。
- 以验收结果决定是否进入下一周，周数是时间预算，不是完成保证。
- 练习环境：Python + PyTorch，前向验证和小模型实验从 CPU 开始，使用 GPU 时记录设备。

## 开始前：30～60 分钟基础自检

- [ ] 能解释 `[B, T, D]` 中批大小、序列长度、隐藏维度的含义。
- [ ] 能算出 `[T, D] @ [D, K]` 的输出形状，并理解 batched matmul。
- [ ] 知道 softmax 如何把一组分数变成概率，知道交叉熵的用途。
- [ ] 能使用 PyTorch 的 `reshape`、`transpose`、`matmul` 和 `backward`。
- [ ] 知道训练循环中的前向计算、损失、反向传播和参数更新。

存在缺项时安排 3～5 次基础练习：矩阵与广播、softmax、线性层与 embedding、自动求导、简单分类训练。补齐能看懂张量运算的基础后，再进入注意力实现。

## 第 1 周：建立完整的数据流

**阅读：** Abstract、§1、§2、§3.1、Figure 1；概览 §4。

**安排：** 2 小时读动机和架构，2 小时画图与标注，2～4 小时复述、补基础和整理问题。

围绕一个翻译例子，标出源序列、目标序列、Encoder 输出和词表概率。把 Figure 1 重画一遍，标明 Encoder 的两种子层、Decoder 的三种子层以及每条残差连接。

要回答的问题：

1. RNN 的序列计算依赖为什么限制训练时的并行性？
2. Encoder 输出的是整段序列的表示，还是一个向量？
3. Decoder 为什么需要 masked self-attention 和 cross-attention？
4. Figure 1 的 “Outputs (shifted right)” 是什么意思？
5. 一个 layer 内的子层与堆叠的 `N` 个 layer 有什么区别？

**产出：** `notes/01-overview.md`，包含自己画的架构图、一次翻译的数据流、术语表和未解决的问题。

**验收：** 不看 Figure 1，用 5 分钟解释整体流程；能指出 Encoder 和 Decoder 的输入、输出以及下一 token 概率产生的位置。原论文中的层结构相同，但不同层通常有独立参数。

## 第 2 周：把单头注意力算明白

**阅读：** §3.2.1、Figure 2 左图、公式 (1) 与脚注 4；选读第 13～15 页。

**安排：** 2 小时推导，1 小时手算，2～3 小时实现，1～2 小时验证和写笔记。

逐步拆解：

```text
Q、K、V → QKᵀ → 除以 √d_k → 加 mask → softmax → 与 V 相乘
```

- 手算一个 `T=3, d_k=d_v=2` 的例子，列出分数、权重与输出。
- 在 PyTorch 中实现 `scaled_dot_product_attention`，返回输出与注意力权重。
- 明确 softmax 沿 key 位置计算，对每个 query 汇总允许读取的 value。
- 区分 causal mask（未来位置不可读）与 padding mask（填充位置不可读）。
- 用脚注中的独立、零均值、单位方差假设，推导点积方差为 `d_k`，解释缩放的理由。

**产出：** `notes/02-attention.md`、`code/attention.py`，以及手算结果和数值验证记录。

**验收：** 在关闭 dropout 时，允许位置上的注意力权重之和约为 1，被屏蔽位置权重约为 0；修改未来位置的 K/V，不影响更早 query 的因果注意力输出。避免给某个有效 query 屏蔽所有 key，否则朴素 softmax 可能出现 NaN。

## 第 3 周：多头注意力与三种使用方式

**阅读：** §3.2.2、§3.2.3、Figure 2 右图，回看 Figure 1。

**安排：** 2 小时阅读与形状推导，2～3 小时实现，2～3 小时检查三种注意力和整理笔记。

- 实现 Q/K/V 投影、拆分 heads、每头注意力、拼接 heads 和输出投影。
- 用下面的形状表追踪多头计算，明确 `transpose` 与 `reshape` 的顺序。
- 分别标注 Encoder self-attention、Decoder masked self-attention、cross-attention 中 Q/K/V 的来源。
- 用 `S=5, T=3` 的例子验证源序列和目标序列长度可以不同。

统一符号：`B` 批大小，`S` 源长度，`T` 目标长度，`D` 模型维度，`H` 头数，`d_h=D/H`。此表使用原版常见设定 `d_k=d_v=d_h`。

| 对象 | Decoder self-attention | Cross-attention |
| --- | --- | --- |
| 拆头后的 Q | `[B, H, T, d_h]` | `[B, H, T, d_h]` |
| 拆头后的 K/V | `[B, H, T, d_h]` | `[B, H, S, d_h]` |
| 分数 / 权重 | `[B, H, T, T]` | `[B, H, T, S]` |
| 每头输出 | `[B, H, T, d_h]` | `[B, H, T, d_h]` |
| 拼接并投影后的输出 | `[B, T, D]` | `[B, T, D]` |

**产出：** `notes/03-multi-head.md`、`code/multi_head_attention.py`。

**验收：** 能解释 cross-attention 的 Q 来自 Decoder 当前子层输入，K/V 来自最终 Encoder 输出；能对照论文指出每个投影矩阵的形状。多头经过不同的可学习投影，并非简单重复同一份注意力计算。

## 第 4 周：组装原版 Encoder–Decoder

**阅读：** §3.1、§3.3～§3.5、公式 (2)，重读 Figure 1。

**安排：** 2 小时理解模块，3～4 小时组装前向计算，1～2 小时逐层检查与记录。

- 实现 FFN：`D → d_ff → D`，中间使用 ReLU；同一层中各位置使用相同参数。
- 实现正弦位置编码，理解 embedding 缩放、embedding 权重共享和输出投影。
- 按原论文顺序实现 `LayerNorm(x + Dropout(Sublayer(x)))`，保留 embedding 与位置编码相加后的 dropout。
- 组装 Encoder Layer、Decoder Layer、层堆叠、embedding 和词表输出层。
- 输入不同长度的源 / 目标序列，记录每个模块的输出形状。

建议实验配置：Encoder 和 Decoder 各 2 层，`D=64, H=4, d_ff=128`。论文 base 模型是各 6 层、`D=512, H=8, d_ff=2048`。模型缩小用于验证架构；简化权重共享等实现时，在笔记中说明。

**产出：** `notes/04-full-model.md`、`code/transformer.py`，完整形状表和与论文的配置差异表。

**验收：** 输入 `[B, S]` 和 `[B, T]` 的 token ID，输出 logits 为 `[B, T, vocab_size]`，前向结果有限且反向传播可运行；在 eval 模式下验证修改未来目标 token 不影响更早位置 logits。此时应能将代码逐块对应到 Figure 1。

## 第 5 周：训练与自回归生成

**阅读：** §5、公式 (3)、§6.1、Table 2。理解 Adam、warmup、dropout、label smoothing 和 BLEU 各自的作用。

**安排：** 1～2 小时阅读，3～4 小时训练与生成，2 小时检查结果和定位问题。

使用小型合成的“数字序列反转”任务：例如源序列 `1 4 2`，目标序列 `2 4 1`。长度取 3～8，词表加入 BOS、EOS、PAD，保存固定随机种子及训练 / 验证样本。小任务能检验 Decoder 是否使用了源序列信息。

- Decoder 输入：`BOS 2 4 1`；监督目标：`2 4 1 EOS`。
- 使用 teacher forcing 和 causal mask，一次前向计算所有目标位置的损失。
- 将 logits 直接交给交叉熵，忽略 PAD 位置；训练循环不需要先手动 softmax。
- 先在几十条固定样本上过拟合，检查损失和训练集上的生成结果，再检查未见样本。
- 实现从 BOS 开始的 greedy generation，逐 token 追加输入，遇 EOS 或长度上限停止。
- 首次过拟合实验可关闭 dropout 和 label smoothing；恢复这些设置时记录变化。
- 首次跑通可使用固定学习率，随后对照公式 (3) 理解并加入论文的学习率调度。

**产出：** `code/train_toy.py`、`code/generate.py`、`experiments/05-toy-task.md`。记录配置、设备、随机种子、loss、整序列匹配率、生成案例和失败案例，区分 teacher-forced 指标与真实生成指标。

**验收：** 小样本训练损失明显下降，并能在关闭 teacher forcing 的生成中正确处理训练样本。单独报告未见样本的结果；能说明训练集过拟合验证了实现可学习，但不代表翻译能力或普遍泛化能力。

**阅读：** 精读 §4、Table 1、§6.2、Table 3、§7，回看全文。

### 回答论文层面的问题

- 区分注意力核心的 `O(T²D)` 与 Q/K/V 投影、输出投影的 `O(TD²)`；FFN 成本约为 `O(TD·d_ff)`。批维度会额外乘上 `B`。

- 选择 Table 3 中两组变体，记录改了什么、结果如何、能支持什么结论。

### 衔接现代架构

整理一张比较表：原版 Encoder–Decoder、Encoder-only、Decoder-only。说明哪些模块保留、哪些移除，mask 与训练目标怎样变化。

认识 Pre-LN、RMSNorm、RoPE、SwiGLU、GQA 各自修改哪个模块。本周先建立对应关系，之后逐项深入。KV Cache、FlashAttention、PagedAttention 作为后续推理工程主题。

### 推导 KV Cache 与两阶段负载

针对标准 Decoder-only 模型，说明为什么历史位置每层的 K/V 可以缓存、为什么历史 query 通常无需缓存，以及为什么仍要读取历史 K/V。

在所有序列长度都是 `T`、缓存不压缩且不考虑分配开销时：

```text
KV Cache 字节数 = 2 × L × B × T × H_kv × d_h × s
```

其中 `L` 为层数、`H_kv` 为 KV 头数、`d_h` 为头维度、`s` 为每个元素字节数；系数 2 对应 K 和 V。MHA 中 `H_kv=H`，GQA 的 KV 头数更少。原版 Encoder–Decoder 还存在 cross-attention 的源序列 K/V，须另行分析。

做一次估算：`L=32, B=1, T=4096, H_kv=32, d_h=128, s=2`，标准 MHA 的 KV Cache 为 **2 GiB**。再将 `H_kv` 改成 8，比较缓存大小。

画出 prefill 与单步 decode 的形状，解释大矩阵计算与权重 / 缓存读取的关系。瓶颈取决于 batch、序列长度、模型与硬件；用算术强度和实际测量判断，不把阶段名称直接当作性能结论。

**产出：** `notes/06-paper-review-and-inference.md`，架构比较表、成本估算与下一阶段的问题清单。

**验收：** 能从 token 输入讲到 logits 输出，再解释训练、生成与缓存。每个现代改进都能对应到原版架构里的一个具体位置。
